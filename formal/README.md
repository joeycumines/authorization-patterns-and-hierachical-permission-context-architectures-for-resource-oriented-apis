# Authorization semantics for v1.8

Run `gmake verify-formal` at the repository root to check the recorded release. On Linux, GNU Make may be installed as `make`. The Lean toolchain version is pinned in [`lean-toolchain`](lean-toolchain) and uses the standard library only. The parity harness uses Node.js 18 or later. The browser runs the reference model embedded in the canonical HTML. [Specification](../index.html) · [Threat model](../docs/security/threat-model.md)

## Working on the specification

1. Edit the normative text, JavaScript model and embedded checks in `index.html`. The simulator and comparison harness share that file’s fixtures.
2. Update the Lean semantics and the section-to-module mapping in `formal/sync-manifest.json`. The recorded digests cover the HTML, model script, single canonical status header (`<span><strong>Status:</strong> Canonical Technical Reference (...)</span>`), formal sources, and Lake configuration (`lean-toolchain` and `lakefile.toml`).
3. Run `gmake record-formal` to build the oracle, audit compiled theorems, exercise the embedded model and parity cases, and run isolated proof mutations. It writes the updated digests after every check succeeds. Run `gmake verify-formal` against the recorded files; any digest change fails verification before the model runs. Do not run concurrent Lean builds while `verify-formal` or `record-formal` is executing.
4. Run `gmake -j check` for the combined model, protobuf, browser, and formal checks. Run `gmake export-md` separately to generate the Markdown outputs in `build/md/`. The root README gives browser setup instructions. [Build targets](../Makefile) · [Browser setup](../README.md)

## Running the oracle

Run the following commands from the repository root. Each input line produces one object containing an `ok` value or an `error` message.

```sh
cd formal
lake --wfail build authz-oracle Authz
echo '{"op":"decide","rules":[{"path":[],"keys":["items.get"],"effect":"permit","pred":null,"hidden":false,"mayError":false,"final":true}],"key":"items.get","path":["items","i"]}' | .lake/build/bin/authz-oracle
```

This example returns `{"ok":"allow"}`. The `query` operation with `protoJson: true` returns the packed transport response when `rulesAllowed` passes, or a `serverFault` error when policy rules violate an `as-written` configuration. A `trace` delivery with `protoJson: true` passes raw JSON to Lean’s grouped receiver and reports receipt actions, target verdicts, scope verdicts, and root listings with holes and tokens. The standalone `evaluateScope` and `usableRegions` operations accept an existing serialized `clientState` (validating service and subject partitioning and newest-first serial order), where `ClientContext` JSON uses normalized internal segment-array anchors rather than tagged wire objects. Legacy envelope-free fixture replay is isolated in `RequestOracle.fixtureOffer`, which synthesizes fixture envelope defaults and skips malformed frames. The `store` operation normalizes an omitted `asWrittenTypes` field to empty, checks initial admissibility, and retains the previous committed state on rejected writes. The `lookupRequest` operation runs the native resource handler through row selection and the final status or structured denial. [Oracle](Authz/Oracle.lean) · [Request oracle](Authz/RequestOracle.lean) · [Store oracle](Authz/StoreOracle.lean) · [Data representations](../hack/formal/codec.js)

The comparison suite loads `window.AuthzModel` from `index.html` and submits independently described fixtures to the Lean executable, comparing whole-response producers, resource handlers, grant compilation, and input validation. Callback fixtures declare their inputs before execution; calls to JavaScript’s deployment-supplied optional-method `undeclaredPolicy` callback are reported separately because Lean always denies `undeclared` methods. The theorem audit inspects all compiled `.thmInfo` declarations across `Authz.*` and `Main` and allows only `propext`, `Classical.choice`, and `Quot.sound`. ## Proof scope and assumptions

The theorems establish conditional properties over the modeled semantic core. Every theorem statement exposes its premises directly in Lean source; the summaries below record the load-bearing assumptions across each area.

*Grants, selectors, and resource names.* Theorem 1.1’s additive form covers valid, unconditional, error-free permits at finite grant sites under a credential ceiling; its singleton converse (`Authz.grant_policy_universal_singleton`, `Authz.Descriptor.singleton_not_collection`) assumes alternating collection and ID segments with no fixed ordinary ID and no ancestor permit. Proposition 3.1 (`Authz.expanded_policy_exact`, `Authz.expanded_projection_exact`) holds with predicates and fault identity under both fail-closed and error-skipping authorities, assuming valid grant sites and valid role selectors. Invalid or empty role selectors fail closed during grant compilation (`Authz.invalid_selector_fails_closed`, covering empty selector lists, undeclared or malformed resource types, and syntactically invalid operations), while `Authz.validateRoleSelectors` also rejects well-formed operations not declared for the selected type at policy or CI validation time so API version evolution does not fail unrelated RPCs at runtime. AIP-156 allows a singleton to have child collections, which fall outside the local alternating catalog; serve that shape via `handler_policy` with an imported, unprojected child type. [Grants](Authz/Grants.lean) · [Descriptor](Authz/Descriptor.lean)

*Offers, enforcement, and Field Guards.* Concrete `ALLOW` (`Authz.method_offer_authorizes`) assumes canonical resolver agreement, complete bindings at one evidence revision, successful required row reads, valid grant sites, and a handler that discharges pending obligations (batch validation can still report invalid input). Concrete `DENY` (`Authz.method_offer_refuses`) covers a protected singular method with complete concrete outer requirements, no active item phase, and a complete row adapter; ceiling refusals hold at any revision, while policy refusals hold at the denying binding’s evidence revision. Universal wildcard `List` (`Authz.wildcard_list_offer_authorizes`) assumes canonical transport, a single protected method with no item filter, a valid descriptor, and winning-token Scoped Claims frames produced at the wildcard anchor under the server’s rules, disclosure settings, and unbudgeted projection (`ListFrameSource`). Alias proofs (`Authz.AliasSoundness`) require a canonical realization preserving fixed segments. Partial-batch item enforcement (`Authz.authorizeRequest_partial_proceed`) is transferred to handlers via the `PARTIAL_BATCH` residual. Field Guard proofs (`Authz.FieldGuards.written_writable`, `Authz.FieldGuards.effectiveMask_unknown_population`, `Authz.FieldGuards.effectiveMask_oneof_sibling`, `Authz.FieldGuards.effectiveMask_strips_output_only`) establish writable-path soundness, fallback on unknown population when the mask is omitted or creation is possible, and real-oneof sibling inclusion; truthful normalized `populated`/`mask` extraction and constraining handler writes remain deployment premises. [Client soundness](Authz/ClientSoundness.lean) · [Alias soundness](Authz/AliasSoundness.lean) · [Field Guards](Authz/FieldGuards.lean) · [Server](Authz/Server.lean)

*Projection and policy authoring.* Scoped Claims preserve pointwise classification over each key’s declared domain, and `Authz.mergeCells_exact` preserves coverage across same-kind cell merges in both profiles. Grant-Shaped skips merges that would retain holes and publishes only hole-free `ALLOW` claims (publishing an allowed child once compatible holes are absorbed, `Authz.grantShaped_publishes_after_absorption`, unless a surviving hole, private boundary, or budget withholds it). `Authz.projection_no_mixed_overlap` proves kind consistency for two claims within one anchor’s `regionClaims`; cross-context conflicts are handled separately at client evaluation. Policy transactions check effective keys against the pinned descriptor and retain the prior store on rejection (`Authz.rejected_commit_retains_store`). Durable visibility is derived from the root through inductive `Nameable` (`Authz.canName_resource_sound`), excluding hidden permits and group permits at unnameable ancestors; a direct visible `Get` permit can still name a resource without parent `List` unless a parent privacy boundary is declared. As-written aliases exclude rule attachment at or below them (`Authz.reachable_as_written_rules`). [Projection](Authz/Projection.lean) · [Policy store](Authz/PolicyStore.lean)

*Disclosure and lookup opacity.* Whole-response privacy-twin proofs (`Authz.Query.response_private_twins`, `Authz.admissible_response_private_twins`, `Authz.reachable_response_private_twins`, `Authz.Query.response_private_forbid_absent`) compare complete responses at fixed public metadata, disclosure settings, and authorized resolutions under admissible stores and a shared global revision (`Authz.Query.distinct_stamps` shows distinct tokens remain observable). Lookup opacity (`Authz.resource_lookup_opacity`, `Authz.inconclusive_lookup_opacity`, `Authz.inconclusive_lookup_diagnostic`) compares two worlds sharing the descriptor, method, request, rules, ancillary rows, and every `ServerOptions` field except the alias lookup (including authority mode, `factsOf`, `faultsOf`, row failures, ceiling, remaining name-resolver settings, `canName`, and `nonprojecting`), differing only in hidden alias mappings and rows. Singular `Create` collision checks live in the reference handler (`Authz.create_collision_requires_read`); `Move` and `Rename` destination collision checks belong to the operation handler. [Query](Authz/Query.lean) · [Lookup](Authz/Lookup.lean)

*Wire receipt and snapshot ordering.* Canonical grouped-wire proofs (`Authz.GroupedReply.canonical_fields_of_query`, `Authz.GroupedReply.canonical_claim_in_table`, `Authz.GroupedReply.canonical_received_stamp`, `Authz.GroupedReply.canonical_received_envelope`, `Authz.grouped_receipt_origin`, `Authz.grouped_offer_sound`, `Authz.grouped_reply_respects_maxProfile`) cover the canonical combined ProtoJSON envelope whenever the key-set table fits signed 32-bit integers (`keySets.length ≤ 2147483647`); detached normalized records are exercised by executable parity checks. Ordering guarantees separate four distinct properties: local winner/floor invariance for a covered query (`Authz.no_resurrection`, `Authz.scope_no_resurrection`, `Authz.no_resurrected_allow`), conflict persistence at a fixed winning snapshot across arbitrary later times (`Authz.conflict_survives_expiry`, `Authz.scope_conflict_survives_expiry`), revision-order non-rollback under conforming fenced replies (`Authz.revocation_never_rolls_back`), and listing non-resurrection under ordered traces that never re-accept retired tokens (`Authz.usableRegions_no_resurrection`). [Wire proofs](Authz/WireScalars.lean) · [Client safety](Authz/ClientSafety.lean) · [Snapshot order](Authz/SnapshotOrder.lean) · [Listing order](Authz/ListingOrder.lean)

## Deployment boundaries

*Registration and IAM.* Inputs describe reflected methods, resources, fields, selectors, and their source declarations. Deployment code obtains that reflection data, authenticates the caller, and commits policy edits atomically. The catalog enforces alternating resource patterns with optional terminal singletons, and a handler can serve a singleton’s child collection through an imported, unprojected type. Explicit-permission writers keep their declared upsert requirements (and can use `Requirement.parent_target` to bind a resource field’s parent), while physical writes still trigger enabled Field Guards. A pure `handler_policy` service with no local resources, at least one `handler_policy` RPC, and no requirement-bearing or undeclared RPCs may omit `api_service` (`Authz.Descriptor.nameless_pure_handler_policy` proves the well-formedness consequence). [Descriptor](Authz/Descriptor.lean) · [Policy transactions](Authz/PolicyStore.lean)

*Rows and aliases.* The deployment supplies truthful alias ownership, current reads, a public candidate range, and consistent row and fault observations for a request. Query disclosure checks every indirect prefix using current-read or ownership evidence; policy authoring requires durable visibility. An unconditional, row-independent decision skips the row read. A failed mandatory read cannot grant access. Handlers must discharge pending search, evaluation, field, and partial-success obligations before exposing data or committing writes. [Disclosure and lookup](Authz/Lookup.lean) · [Server](Authz/Server.lean)

*Wire and time.* Both models implement the grouped ProtoJSON boundary. For a canonical query whose key-set table fits signed `int32`, each received claim traces back to its original group and the producer’s service, descriptor ETag, subject, revision, and profile. Production transport supplies authenticated bytes, absolute clocks, and revision fencing. Raw JSON `null` omits a schema field; a `null` array element fails validation, and native normalized cache records undergo their own shape checks. A subject switch at an existing token requires the current dispatch floor. Concurrent identity-provider updates at a fixed policy revision remain unordered in this protocol and can briefly shift advisory offers, whereas server RPCs evaluate current authority and clients refresh on `PERMISSION_DENIED`. [Wire proofs](Authz/WireScalars.lean) · [Ordering](Authz/SnapshotOrder.lean)
